# MineUI 新增能力需求（音乐 UI 驱动）

> 需求来源：MineAudio（2026-09-18）。本需求由音乐场景驱动，但均做成**通用能力**。
> 关联：音频与状态来源见配套流媒体客户端 Mod 需求（MineAudio 仓库）。

## MineUI 评估结论（2026-09-18，已确认）

| 决策点 | 结论 |
|---|---|
| 平台 | **只实现 Minecraft 26.2**（客户端 mod 单版本构建） |
| 远程图片 | **客户端直连 HTTPS** + 服务端下发的域名白名单/清单（sha256 + 尺寸）+ 私网/回环拦截 |
| HUD 与屏幕组件 | 同一套 JSON 节点与渲染器，HUD 复用会话/状态/patch；`OPEN` 增加 `mode: "hud"` + `HudLayout` |
| HUD 与屏幕并存 | 服务端会话改为"一个屏幕 + 若干 HUD/玩家"；开屏幕只替换旧屏幕，开 HUD 只替换同 app/view 的旧 HUD |
| 本地偏好 | `config/mineui/client.json`；逐 app/view 覆盖 > 总开关 > 服务端默认 |
| 插值 | 只作用于 `progress.value`（及滑块显示）；按本地时钟线性外推，seek 超阈值立即对齐 |
| 进度条 | 专用 `progress` 组件（非数值宽度绑定） |
| 歌词/队列 | 通用 `list` 节点（items 绑定 + itemTemplate + highlightIndex + 自动滚动居中） |
| 键位 | 客户端预注册通用键位池 + 服务端 `KEYBIND` 声明含义；本阶段先落地本地 HUD 开关（F6） |
| 与 §62 规划 | 以此实现为准，合并官方 HUD 规划 |

**阶段状态**：
- ✅ **P1 HUD 基础**（0.8.0）：HUD 会话（`openHud`）、锚点/偏移/缩放、客户端偏好与 F6 总开关、生命周期清理、能力位 `hud_v2`、`/mineui hud` 演示
- ⏳ P2 进度条 + 客户端插值 + 滑块增强（step/禁用态/只读）
- ⏳ P3 远程图片（异步下载/缓存/白名单/私网拦截/占位降级）
- ⏳ P4 list（歌词/队列）+ Toast + 服务端声明键位

## 1. 背景与目标

MineUI 已能承载屏幕页面（会话 / 状态 / 动作 / 组件 / 动态贴图 / 3D 预览），MineAudio 的
`/mineaudio ui` 已在使用。但要做“音乐播放器”体验还缺：

- **HUD**：MoeMusic 的“正在播放”卡片是客户端本地渲染，服务端不可控；MineUI 的 HUD Overlay
  仍在规划中（设计文档 §62）
- **远程图片**：网易云封面等是远程 URL，MineUI 目前只能渲染资源包/内置贴图
- **进度条**：需要数值绑定或专用组件；进度要平滑，不能靠高频网络包
- **交互细节**：拖动滑块（seek/音量）、按键打开界面、歌词高亮滚动等

目标：把这些能力做进 MineUI，避免每个业务插件各自造轮子；MineAudio 只通过服务端下发
状态与动作，不依赖任何客户端专用 UI。

## 2. 范围

- 只做 UI 能力；不包含音频播放与流媒体协议
- 状态来源：业务插件通过 MineUI 现有/新增 API 下发
- 通用性要求：HUD、远程图片、进度条等不做成音乐专用，验收时需用非音乐场景验证

## 3. 功能需求

### FR-1 HUD Overlay 框架
- 声明式：复用现有 JSON 节点（text / box / image / item / …）描述 HUD
- 服务端下发默认布局：`anchor`、`offset`、`scale`、`visible`、`z`
- 与屏幕会话独立生命周期：owner 插件管理；玩家退出 / 切服 / 插件停用自动清理
- 客户端本地可覆盖：总开关、位置、缩放（个人偏好优先），本地持久化
- 安全区：默认避开原版计分板、hotbar、BossBar 等区域，或提供 safe-area 约束
- 更新走现有状态 patch；HUD 常驻渲染成本可控

### FR-2 远程图片 / 封面渲染
- 通过 HTTPS URL 拉取图片并作为 `image` 节点渲染
- 安全限制：仅 HTTPS、域名白名单/黑名单、拒绝私网与本机地址、大小与格式限制
- 异步加载不阻塞渲染；加载中 / 失败有占位与降级
- 缓存：内存 + 磁盘上限、LRU 清理；退出/切服清理句柄
- 可选：圆形裁剪、旋转等展示效果
- 只解码图片，不执行任何远程代码

### FR-3 数值绑定与进度条
- `progress` 组件：`min` / `max` / `value`、背景与填充样式、方向、圆角
- 时间文本（进度 / 总时长）格式化；或由业务侧拼好字符串

### FR-4 客户端平滑插值（低频更新）
- 服务端 1Hz 下发进度即可，客户端按本地时间在两次更新间插值
- 节点声明式开启（`interpolate: true`）；暂停 / seek / 切歌时立即对齐
- 不增加网络频率

### FR-5 滑块增强（seek / 音量）
- 拖动中（预览值）与提交（松开）分离
- 值双向绑定：服务端状态变化能更新滑块位置
- 禁用态 / 只读态；步进与吸附

### FR-6 客户端键位
- 服务端可声明“按某键打开 app/view”
- 冲突处理与本地改键；未安装 mod 的玩家不受影响
- 界面按钮可显示当前按键提示

### FR-7 高亮列表 / 歌词视图
- 滚动文本列表 + 当前行高亮 / 居中
- 逐行样式；自动滚动到当前行

### FR-8 通知 / Toast（可选）
- 服务端短提示（切歌、错误等），支持图标与点击动作

### FR-9 本地偏好持久化
- HUD 开关 / 位置 / 缩放等客户端本地保存；服务端只给默认值

### FR-10 性能与生命周期
- HUD 与屏幕同时存在时的渲染顺序与资源占用可控
- 批量 patch；玩家退出 / 切服 / 断线彻底清理（无残留 HUD、图片句柄）

### FR-11 安全与权限
- HUD 与页面内容仅服务端权威；客户端只渲染
- 远程资源同受防火墙约束，不把客户端 IP 暴露给任意主机

## 4. 与现有 API 的关系

- 屏幕：`MineUi.open` / `session.state` / `session.on` / `session.snapshot` / `session.close` 保持不变
- HUD：`MineUi.openHud(owner, player, app, view, definition, layout)`（owner 生命周期、state / on / snapshot）
- 能力位：`server_ui`、`hud_v2`；业务插件按能力降级
- 服务端只提供状态；具体展示由页面 / HUD 的 JSON 决定

## 5. 验收场景（含通用性验证）

1. 音乐：`/mineaudio ui` 显示真实曲目、进度、封面；HUD 显示“正在播放”，服务端可调位置/缩放/关闭；计分板仍可显示文本
2. 音乐：未装流媒体 mod 时 UI 自动降级（无进度/封面）且不报错
3. 通用：另一个插件用 HUD 显示倒计时 / 比分
4. 性能：HUD + 屏幕同时开启，帧率无明显下降；1Hz 更新下进度平滑
5. 安全：非白名单图片 URL 被拒绝；HUD 在切服 / 退出后无残留

## 6. 非功能需求

- 平台：Minecraft 26.2（Paper 插件 + Fabric mod）
- 版本：能力位与协议向后兼容；旧客户端遇到未知节点/绑定安全跳过
- 性能：图片缓存上限、HUD 渲染开销、内存占用需有明确上限
- 安全：远程资源白名单、拒绝私网
